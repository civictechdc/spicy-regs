Control 5 finding (new, 2026-07-28): a minted rkaf:requestContractDigest on
a non-model rkaf:ExtractionActivity is NOT caught by any gate. Core §2.4
is explicit — "A digest over an envelope minted to satisfy the field is
non-conforming" — but every compiled surface checks only the lexical form
^sha256:[0-9a-f]{64}$ (compiled/json-schema/core/extraction-activity
.schema.json, compiled/shacl/core/extraction-activity.ttl), and the
conditional guard that fires on rkaf:modelExtraction requires presence, not
absence, under the other four methods. Verifying the claim would need the
preimage of a digest the kernel treats as opaque by design, so no shape can
express it. This is a producer obligation in the same class as Core §4.7.3
rule 3 and the §2.1 projected-edge rules: real, normative, unmechanized.
The four controls above are what the gates DO catch; this fifth one marks
the boundary.
